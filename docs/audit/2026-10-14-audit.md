# Agnostik Security Audit — 2026-10-14 (v1.6.5 toolchain refresh)

**Pass type:** the pre-release security pass required by CLAUDE.md §"Security
Hardening (before every release)", scoped to a toolchain bump.
**Scope:** the cyrius security advisories published between the old pin and the
new one, judged against what agnostik actually reaches. Also the re-vendored
stdlib, the syscall sites in `src/` on every target the pin builds, the new
`cyrius.lock`, and the changed distribution sidecar.
**Toolchain:** cyrius `6.6.6` → `6.6.20`.

**No findings.** No agnostik source changed, apart from two comments. One
advisory, CYRIUS-2026-0028, reaches agnostik code, and agnostik's caller was
never exposed to it. The 1.6.5 re-vendor brings the fixed `lib/fmt.cyr` anyway.

## Threat model

Unchanged from [`2026-09-23-audit.md`](2026-09-23-audit.md). The inputs are
untrusted JSON, version, UUID and traceparent strings crossing the serde
boundary, plus the CSPRNG and the fatal stderr message. Target portability
stays an axis: a raw syscall number is judged on every target, not only
x86_64-linux.

## Advisories in range

Cyrius published CYRIUS-2026-0009 through CYRIUS-2026-0035 between 6.6.7 and
6.6.20. agnostik vendors only `alloc`, `assert`, `bayan`, `boxed`, `chrono`,
`fmt`, `fnptr`, `hashmap`, `hashseed`, `io`, `result`, `str`, `string`,
`tagged`, `trait`, `vec`, `syscalls`, and their platform peers. "Dead" below
means `CYRIUS_DCE_VERBOSE=1` lists the fn as eliminated from the release
binary.

| Advisory | Area | Reaches agnostik? |
|---|---|---|
| **CYRIUS-2026-0028** (P1) | `lib/fmt.cyr` `fmt_int_buf` wrote 24 bytes at `buf` whatever the number's length | **Yes, not exploitable.** See below |
| CYRIUS-2026-0034 (P2) | `lib/io.cyr` `file_write_atomic` symlink race on its temp name | No: `file_write_atomic` is dead |

| CYRIUS-2026-0033 (P2) | aarch64 frame displacements past 64 KiB | No: `src/` declares no stack arrays, so every frame is small |

### CYRIUS-2026-0028 and `version_to_str`

`version_to_str` (`src/types.cyr`) formats the three numeric components with
`fmt_int_buf` at `buf + pos`, which is the calling pattern the advisory
describes. Up to 6.6.17, `fmt_int_buf` built its digits from `buf + 23`
downward, so every call wrote 24 bytes at `buf + pos` whatever the number's
length.

agnostik's buffer is `alloc(128)`. The third call starts at most at `pos = 42`
(a 20-character `i64` minimum, a `.`, another 20 characters, and a `.`), so
the widest scratch write ends at `buf + 66`. Bytes past the formatted number
are scratch that the following writes overwrite in order. The prerelease and
build suffixes are bounded by `cap = 127`. A probe built the widest possible
string on both pins:

```
-9223372036854775808.9223372036854775807.-1-rc.1+sha.0123456789abcdef
```

It came out correct, 69 bytes, on 6.6.6 and on 6.6.20. 6.6.18's
`fmt_int_buf` writes exactly `len + 1` bytes, so the margin is now wider.

## Syscall sites, every target

The sites are unchanged since v1.6.3. `src/types.cyr` reaches the stdlib's
`sys_getrandom`, `sys_write` and `sys_exit`. `src/error.cyr` has four raw
`syscall(1, 2, …)` stderr writes. 1 is `write` on x86_64-linux and agnos, and
is routed on aarch64 and Windows. `CYRIUS_DCE=1` builds succeed for
x86_64-linux, aarch64, agnos and Windows, with no warning from agnostik
source. The Windows build prints one warning from the stdlib's own
`lib/syscalls_windows.cyr:436` (a one-argument `syscall 12`). 6.6.6 printed a
broader, generic routing warning for the same target. The v1.7.1 roadmap slot
moves the four raw sites to `sys_write` and gates `src/` against new ones
([ADR-003](../adr/003-roadmap-tracks-agnostik-work-only.md)).

## Verified sound (negative results)

- **Vendored stdlib.** All 33 `lib/` files are byte-identical to the 6.6.20
  snapshot. 29 changed content since 6.6.6 (including the git-tracked
  `keccak.cyr`, which nothing includes), 3 did not (`alloc_agnos`,
  `args_macos`, `fnptr`), and `poison.cyr` is new.
- **Published toolchain.** `cyrius-6.6.20-x86_64-linux.tar.gz` matches its
  `.sha256` sidecar. Its `lib/` and every binary agnostik uses are
  byte-identical to the local install; only the bundled `bin/ci.sh` helper
  differs. Every `ci.yml` step passed in a throwaway `HOME` built from that
  tarball the way CI builds it.
- **`cyrius.lock`.** It is new at 1.6.5, written by `cyrius deps`, which since
  6.6.9 locks a stdlib-only project. It covers all 33 files.
  `cyrius deps --verify` gives 33 verified, 0 failed. A fresh `lib sync` +
  `deps` reproduces it byte for byte.
- **Distribution sidecar.** `dist/agnostik.deps` is now what the 6.6.18
  compile-verify proves the bundle needs: 15 leaves become 12, dropping
  `tagged`, `fnptr`, `assert` and `io` and adding `boxed`. Of the five repos
  that declare `[deps.agnostik]`, only anuenue does not declare `tagged` and
  `fnptr` itself, and its source calls neither. kybernet, rebuilt on its own
  6.6.6 pin with the new bundle swapped in, produced a binary of the same size
  as before.
- **CI security scan**, run verbatim: no raw `execve`/`fork`/`clone`, no
  `sys_system`, no `/etc` / `/bin` / `/sbin` literals, no stack buffer of
  64 KB or more.
- **F-001..F-024** remain closed.

## Observations (not findings)

- **Symbol collision in a consumer.** kybernet vendors agnostik and sigil, and
  its build warns `duplicate fn '_hex_nibble' (last definition wins)`. The two
  definitions have the same arity and mapping, so behaviour is unaffected. It
  is the class that broke `health_check_new` in 1.6.1, so private-helper
  namespacing is pinned to v1.7.0.

## Conclusion

Ship. No findings. The one advisory that reaches agnostik code did not
expose it, and its fix arrives with the re-vendor.
