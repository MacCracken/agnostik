# Agnostik Security Audit — 2026-10-28 (v1.12.1 toolchain refresh, v1.12.2 CI pass)

**Pass type:** the pre-release security pass required by CLAUDE.md §"Security
Hardening (before every release)", scoped to a toolchain bump.
**Scope:** the cyrius security advisories published after the old pin, judged
against what agnostik reaches; the silent semantic changes in 6.7.10–6.7.18;
the re-vendored stdlib; the syscall sites in `src/` on every target; the new
`cyrius.lock`; and toolchain integrity.
**Toolchain:** cyrius `6.7.9` → `6.7.18`.

**No findings.** No agnostik source changed. No advisory in range reaches code
agnostik calls, and every test file prints identical output on both pins.

## Threat model

Unchanged from [`2026-10-14-audit.md`](2026-10-14-audit.md). The inputs are
untrusted JSON, version, UUID and traceparent strings crossing the serde
boundary, plus the CSPRNG and the fatal stderr message. Target portability
stays an axis: a syscall site is judged on x86_64-linux, aarch64, agnos and
Windows.

## Advisories in range

The cyrius security ledger (`docs/audit/2026-10-08-security-ledger.md` in the
cyrius repo) lists CYRIUS-2026-0036 through CYRIUS-2026-0050 after the 6.7.9
pin, most of them found by cyrius's 2026-10-22 audit and fixed or mitigated by
6.7.18. agnostik's `[deps] stdlib` is `syscalls`, `string`, `alloc`, `str`,
`fmt`, `vec`, `hashmap`, `tagged`, `result`, `fnptr`, `trait`, `assert`, `io`,
`bayan` and `chrono`, with their platform peers and transitive includes.

- **0045.** `bayan` is vendored, and since 6.7.17 the `#derive(Serialize)`
  expansion of `T_from_json_str` calls `bayan_json_get_by_str`. That JSON
  lookup is the only `bayan` fn agnostik's code reaches. `src/` calls no
  `bayan_*` fn and no PDF decoder.
- **0047.** `src/` calls neither `file_write_atomic` nor `_aw_open`. agnostik
  writes no files.
- **Consumers.** Each consumer vendors `bayan` and `io` at its own pin, through
  `dist/agnostik.deps`. A consumer that parses PDFs or writes files through
  those fns gets the fixes by moving its own pin to 6.7.18, whatever agnostik
  pins.

## Silent changes in 6.7.10–6.7.18, checked against `src/`

The cyrius CHANGELOG and its ecosystem-migration notes were read for every
release in range. Each change that alters compiled code without a diagnostic
was checked against `src/`:

- **Packed `u8` / `u16` / `u32` / `f32` struct fields (6.7.10):** agnostik's
  narrow fields are all `i8`, which is unchanged (`InjectionScores`,
  `AcceleratorFlags`).
- **Struct values, copies and operator fns (6.7.10–6.7.17), inline `Str` and
  typed `Str` methods (6.7.13–6.7.17), narrow parameter and global widths
  (6.7.16), zone constant folding (6.7.14):** not used. `: Str` appears only on
  handle parameters, there are no narrow parameters, and all 32 globals have
  literal initializers.
- **`T_from_json_str` walks each field's value whole (6.7.11, 6.7.13):** this
  reaches agnostik's seven derived structs. A value that is an object, an array
  or the wrong type no longer leaks its inner keys into the outer struct; the
  new answers are the correct ones, and agnostik's tests print identical output.
  It costs the five derived-parser benchmarks 11–28% (CHANGELOG
  §Performance).

## Re-vendored stdlib

`lib/` was re-vendored with `cyrius deps` at the new pin. Since 6.7.13 a
scoped `lib sync` refuses a pin move while `lib/` holds changed transitive
leaves. The lock covers 41 files, up from 32: `bayan` 1.11.1 now includes
`math`, `slice` and seven `lib/unicode/` files. A fresh checkout reproduces
it byte for byte, and `deps --verify` reports 41 verified, 0 failed.

- `string`, `hashmap`, `tagged`, `trait` and `assert` are byte-identical.
- The `alloc`, `fmt`, `fnptr` and `hashseed` changes are comments only;
  `alloc` still returns 0 on failure.
- `str.cyr` gains three public fns (`str_builder_add_json_cstr`,
  `str_json_unescape`, `str_json_unescape_cstr`). A name scan of agnostik's
  fns against the vendored stdlib found no collision.
- `.gitignore` now ignores `lib/**/*.cyr`. The old `lib/*.cyr` left the new
  `lib/unicode/` files untracked but committable.

## Syscall review

`src/` is unchanged and still has three syscall sites, all through the stdlib
wrappers: `sys_getrandom` (the CSPRNG), `sys_write` (stderr, five calls) and
`sys_exit`. Their definitions in `syscalls_linux_common`,
`syscalls_x86_64_agnos` and `syscalls_windows` are byte-identical to 6.7.9's.
The aarch64 peer routes through `syscalls_linux_common`. The other syscall
changes in range (agnos negative fds, Windows errno mapping in `sys_read`, the
`cx` `fstat`) are on paths agnostik does not call. The DCE builds are
warning-free on x86_64, aarch64, agnos and Windows.

## Toolchain integrity

The 6.7.18 release tarball was installed through
`scripts/ci-install-cyrius.sh` into a scratch `CYRIUS_HOME`. `SHA256SUMS.sig`
verifies against the pinned cyrius release key, and the tarball verifies
against `SHA256SUMS`. Its `lib/` and its `cycc`, `cycc_aarch64`, `cycc_win` and
`cyrius` binaries are byte-identical to the local install. The key is
unchanged.

## Re-scan

The CI security scan is clean: no raw `syscall(`, no `sys_system`, no `/etc`
/ `/bin` / `/sbin` literal, and no stack buffer of 64 KB or more. The
private-helper gate passes. F-001..F-027 remain closed.

**Conclusion: ship 1.12.1.**


## v1.12.2 release pass (same day)

**Pass type:** the security pass every release runs. **Scope:** the CI and release workflows: four action majors
moved, ci.yml given a read-only token, the runner image moved from `ubuntu-latest` (24.04) to `ubuntu-26.04`, and the toolchain installer no longer
uses `xxd`. No agnostik source, API, stdlib or toolchain change.

**No findings.**

- **Action versions.** Each workflow keeps referencing actions by floating major tag. Each tag was resolved through
  the GitHub API at the time of the change; all four point at their latest stable release:

  | Action | Was | Now | Commit the tag resolves to (2026-10-28) |
  |---|---|---|---|
  | `actions/checkout` | v4 | **v7** (v7.0.1) | `3d3c42e5aac5ba805825da76410c181273ba90b1` |
  | `actions/upload-artifact` | v4 | **v7** (v7.0.2) | `cf430e030ddbb5b0abf93d22962f4752f3646cd9` |
  | `actions/download-artifact` | v4 | **v8** (v8.0.2) | `9000827ccba6bdab643e8b6fd33ac0654aef8333` |
  | `softprops/action-gh-release` | v2 | **v3** (v3.0.3) | `efb35369e0ad2afab669f228072c1b0d510eae64` |

- **Release notes, read for every major crossed:**
  - **checkout:** v5 moves to Node 24. v6 keeps persisted credentials in a separate file. v7 refuses to check out
    fork PRs under `pull_request_target` / `workflow_run`. agnostik uses neither trigger, and `fetch-depth: 0`
    (the paired bench gate) is unchanged.
  - **upload-artifact:** v5 and v6 move to Node 24. v7 adds an opt-in `archive: false`; the default still zips,
    so the release artifact is unchanged.
  - **download-artifact:** v5's path change applies only to single downloads by ID, while release.yml downloads
    by name. v8 skips unzipping non-zipped files, and **fails on a digest mismatch by default**, where it used to
    warn. That is an integrity gain for the release job.
  - **action-gh-release:** v3 is the Node 24 runtime only.
- **Advisories.** The GitHub advisory database lists one advisory for these actions, GHSA-cxww-7g56-2vh6
  (`download-artifact` >= 4.0.0, < 4.1.3, arbitrary file write on extraction). The floating `v4` tag was already
  past it, and v8 is out of its range. There are none for the other three.
- **Permissions.** ci.yml now declares `permissions: contents: read`. Until now it declared none, so its token
  took the repository default, which can be read-write. Under release.yml's `workflow_call`, that narrows the
  caller's grant. release.yml alone asks for `contents: write`, which creating the release needs.
- **Runner image.** `ubuntu-26.04` has been GA since the runner-images announcement (actions/runner-images#14747),
  and `ubuntu-latest` moves to it in November 2026.
  - It replaces GNU coreutils with **uutils 0.10.0** (Rust), and its awk is **mawk**.
  - It ships **no `xxd`**: the base image lacks it and the runner toolset does not list it.
- **Toolchain installer without `xxd`.** `scripts/ci-install-cyrius.sh` checked for `xxd` and refused to run without
  it, which on 26.04 would stop every CI job at its second step.
  - It now builds the pinned key's SubjectPublicKeyInfo DER with bash's `printf` `\xHH` escapes, after checking
    that the key is 64 hex digits and that the DER is 44 bytes.
  - The DER is byte-identical to `xxd -r -p`'s (same SHA-256).
  - A real 6.7.18 release still verifies, with binaries byte-identical to the local install.
  - With one nibble of the pinned key changed, the signature check fails closed and nothing is installed.
  - CI's "Verify ELF" step reads the magic with `od` instead.
- **Re-scan.** `src/` is unchanged since 1.12.1; F-001..F-027 remain closed.

**Conclusion: ship 1.12.2.**
